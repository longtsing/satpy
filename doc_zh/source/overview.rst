========
概述
========

Satpy 旨在提供对处理气象遥感数据的常见操作的便捷访问。执行这些操作所需的任何细节都在 Satpy 内部配置，这意味着用户不必担心*如何*完成某事，只需要请求他们想要的内容。Satpy 提供的大多数功能都可以通过关键字参数进行配置（有关更多详细信息，请参阅 :doc:`API 文档 <api/satpy>` 或其他特定部分）。
对于更复杂的自定义或添加功能，Satpy 使用一组可由用户修改的配置文件。Satpy 的各种组件和概念如下所述。:doc:`quickstart` 指南还为 Satpy 的可用功能提供了简单的示例代码。

Scene（场景）
=============

Satpy 通过 :class:`~satpy.scene.Scene` 类提供其大部分功能。这充当正在操作的数据集的容器，并提供对这些数据集进行操作的方法。它试图减少用户所需的低级知识量，同时仍然为底层功能提供 Pythonic 接口。

Scene 对象表示单个地理区域的数据，通常在单个连续时间范围内。可以组合多个 Scene 以形成具有多个区域或多个时间观测的 Scene，但不能保证所有功能在这些情况下都能正常工作。

DataArrays（数据数组）
======================

Satpy 的底层数据容器是 :class:`xarray.DataArray`。由于历史原因，DataArray 在 Satpy 中通常被称为"Datasets"（数据集）。这些对象的行为类似于普通的 numpy 数组，但添加了额外的元数据和属性来描述数据。元数据存储在 ``.attrs`` 字典中，命名维度可以在 ``.dims`` 属性中访问，以及其他属性。
在大多数使用情况下，这些对象可以像普通的 NumPy 数组一样操作，特别注意确保元数据字典包含预期值。有关处理 :class:`xarray.DataArray` 对象的更多信息，请参阅 XArray 文档。

此外，Satpy 使用一种特殊形式的 DataArray，其中数据存储在 :class:`dask.array.Array` 对象中，这允许 Satpy 执行多线程延迟操作，大大提高处理性能。
有关使用 dask 和 xarray 进行开发的帮助，请参阅 :doc:`dev_guide/xarray_migration` 或特定项目的文档。

为了唯一标识 ``DataArray`` 对象，Satpy 使用 `DataID`。``DataID`` 由各种可用的元数据片段组成。这通常包括 `name` 和 `wavelength` 作为识别元数据，但也可以包括 `resolution`、`calibration`、`polarization` 和额外的 `modifiers` 以进一步区分一个数据集与另一个数据集。有关 `DataID` 对象的更多信息，请查看 :doc:`dev_guide/satpy_internals`。

.. warning::

    XArray 包含其他称为"Datasets"的对象类型。这些与 Satpy 中提到的"Datasets"不同。

数据块
------

Satpy 的操作以 dask 为基础，这意味着底层数据被分块，即切成可以并行处理的较小片段。有关 dask 分块的信息可以在 dask 文档中找到：https://docs.dask.org/en/stable/array-chunks.html
这些块的大小可能对 satpy 的性能产生重大影响，因此为了获得最佳性能，可能需要调整它。

Satpy 使用的默认块大小可以通过在代码周围使用以下内容进行配置：

.. code-block:: python

    with dask.config.set({"array.chunk-size": "32MiB"}):
      # 你的代码在这里

或者使用：

.. code-block:: python

    dask.config.set({"array.chunk-size": "32MiB"})

在代码顶部。

还有其他方法可以设置 dask 配置项，包括配置文件或环境变量，请参见：
https://docs.dask.org/en/stable/configuration.html

块大小的值可以以不同的方式给出，请参见：
https://docs.dask.org/en/stable/api.html#dask.utils.parse_bytes

此参数的默认值为 128MiB，对于 64 位浮点数组，这可以转换为 4096x4096 的块大小。

但是请注意，某些读取器可能会选择对块大小进行自由解释，这不一定会产生方形块，甚至不一定是确切请求大小的块。这背后的动机是，以条带存储的数据如果尽可能保持水平条带而不是将数据切成方形块，则可能加载得更快。但是，Satpy 读取器应该在有意义的情况下尊重总体块大小。

.. note::

    在 Satpy 中提供块大小的传统方法是 ``PYTROLL_CHUNK_SIZE`` 环境变量。这现在正在等待弃用，因此实现相同结果的等效方法是使用 ``DASK_ARRAY__CHUNK_SIZE`` 环境变量。要分配给该变量的值是传统变量的平方，乘以手头数组数据类型的大小，因此例如，对于 64 位浮点数::

      export DASK_ARRAY__CHUNK_SIZE=134217728

    这与以下相同::

      export DASK_ARRAY__CHUNK_SIZE="128MiB"

    等同于已弃用的::

      export PYTROLL_CHUNK_SIZE=4096

读取
====

使用 Satpy 的最大优势之一是它可以读取大量输入文件格式。它将此功能封装到各个 :doc:`reading` 中。Satpy 读取器处理读取它们所代表的任何格式的所有复杂性。气象卫星文件格式可能极其复杂，并且格式很少在卫星或仪器之间重复使用。无论格式如何，Satpy 的读取器接口都旨在提供一致的数据加载接口，同时仍然提供添加新的复杂文件格式的灵活性。

合成
====

许多卫星图像用户结合多个传感器通道来突出数据的某些特征。这包括使用一个数据集来增强另一个数据集，将 3 个或更多数据集组合成 RGB 图像，或数据集的任何其他组合。Satpy 内置了许多常见的合成组合，并允许用户像请求任何其他数据集一样请求它们。Satpy 还可以创建您自己的自定义合成，并让 Satpy 像对待任何其他数据集一样对待它们。有关更多信息，请参阅 :doc:`composites`。

重采样
======

卫星图像数据在地理定位方面有两种形式：原生卫星扫描坐标和统一网格投影坐标。还常见于看到来自单个传感器的通道具有多种分辨率，这使得组合或比较数据集变得复杂。卫星数据的许多使用情况要求数据处于除原生投影之外的某种投影中，或者使输出图像覆盖特定的感兴趣区域。Satpy 使重采样数据集变得容易，允许用户将它们组合或网格化到这些投影或感兴趣区域。Satpy 使用 PyTroll `pyresample` 包提供最近邻、双线性或椭圆加权平均重采样方法。有关更多信息，请参阅 :doc:`resample`。

增强
====

从卫星数据制作图像时，必须对数据进行处理以与输出图像格式兼容，并且仍然对人眼看起来美观。Satpy 将此功能称为"增强"数据，也通常称为缩放或拉伸数据。这个过程可能变得复杂，不仅因为图像质量的主观性，还因为预报员和其他用户对数据应该如何呈现的历史期望。Satpy 试图隐藏所有可能的增强方法的复杂性，默认情况下只提供最佳外观的图像。Satpy 仍然可以自定义这些程序，但在大多数情况下应该没有必要。有关输出格式和增强图像可能性的更多信息，请参阅 :doc:`writing` 文档。

写入
====

Satpy 旨在使数据加载、操作和分析变得容易。然而，将卫星图像数据以尽可能多的格式提供给尽可能多的用户的最佳方法是使其易于保存为多种格式。Satpy 允许用户将数据保存为 PNG 或 GeoTIFF 等图像格式以及 NetCDF 等数据文件格式。每种格式的复杂性都隐藏在各个 Writer 对象的接口后面，并包括用于访问特定格式功能（如压缩和输出数据类型）的关键字参数。有关可用的写入器及其使用方法，请参阅 :doc:`writing` 文档。
